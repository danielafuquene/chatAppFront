# Ejecutar esta feature

1. Lee `../../governance.md` y `../../architecture.md` antes de hacer cualquier otra cosa. Esas reglas valen para todas las features.
2. Lee `spec.md` y `files.md` en esta misma carpeta.
3. Si la spec contradice governance o architecture, mandan esos dos archivos. Si governance y architecture se contradicen, detente y pregunta.
4. Muestra el plan con los archivos de `files.md` y detente. No crees ni edites archivos de la app.
5. Ejecuta solo cuando el mensaje tenga esta frase, tal cual: Apruebo el plan y autorizo los cambios listados.
6. No instales `expo-sqlite` hasta que el mensaje tenga esta frase, tal cual: Apruebo instalar expo-sqlite.
7. Sigue `files.md`, un archivo por paso. Usa solo las pantallas, los types y las librerías de `spec.md`.
8. Las dudas de `spec.md` siguen abiertas. No inventes el path del endpoint, el dato de no leídos, el dato de favoritos, el texto del último mensaje, los estados de carga, error o lista vacía, ni la fila `Tú · Notas`.
9. Al terminar, escribe en `bitacora.md` qué archivo se tocó, qué quedó hecho y qué duda sigue abierta.
